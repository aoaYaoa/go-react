# Grok Media Command Semantics Design

**Date:** 2026-03-07

## Goal
把 `grok-media` 的命令语义拆清楚：`/edit` 用于保真编辑，`/imagine` 用于自由重绘/自由生成，避免“用户想保留同一人物却用了 /imagine”时得到完全无关的新图。

## Decision
- `/edit`：带图编辑，强调保留同一人物、脸部、发型、服装、背景、镜头和构图，只改用户要求的动作/姿势/表情等。
- `/imagine`：自由生成。即使当前对话里存在图片，也不再自动切换到编辑流。
- 不新增复杂命令状态机，保持插件实现简单，重点通过命令语义和 prompt 约束解决问题。

## Why
- 自动把“带图 /imagine”切到编辑流虽然更智能，但会让两个命令的边界变模糊。
- 用户已经明确选择方案 3，需要命令语义稳定可预期。
- 当前更严重的问题不是没走编辑接口，而是编辑 prompt 太弱，导致模型把编辑理解成重生成。

## Changes
1. 取消 `带图 /imagine -> /edit` 的自动切换。
2. 给 `/edit` 和 `grok_edit_image` 使用更强的保真编辑 prompt 模板。
3. 更新测试：
   - `/imagine` 带图时仍走 imagine 接口
   - `/edit` 请求体 prompt 包含保真约束和原始用户指令
4. 部署后做一次真实验证。
